# wedding-feast 项目开发计划书

> 版本：MVP v0.1  
> 基准文档：[`项目PRD.md`](./项目PRD.md)、[`样式.md`](./样式.md)  
> 目标：先完成可用的宾客管理与桌次安排，再逐步扩展

---

## 1. 项目定位

本项目是一个婚礼宾客管理与可视化排桌工具。

第一阶段只做两件事：

1. 宾客名单管理
2. 桌次安排与现场布局

所有开发都围绕“快速录入、直观查看、拖拽排座、稳定保存”展开。

---

## 2. 设计目标

UI 以 [`样式.md`](./样式.md) 为准，整体方向是：

- 漫画书视觉语言
- 强对比、粗线条、鲜明色块
- 动态分格与动作感
- 信息清晰、操作直接

但在婚礼业务场景下，视觉表达要控制在“有风格但不喧宾夺主”的范围内，避免影响表单、列表、画布的可读性。

---

## 3. MVP 范围

### 3.1 必做功能

- 宾客 CRUD
- 宾客搜索
- 宾客统计
- Excel 导入 / 导出
- 桌子创建、编辑、删除
- 圆桌座位分配
- 桌子拖拽
- 宾客拖拽入座
- 点击安排座位
- 移除座位
- 现场布局保存

### 3.2 暂不做

- 登录注册
- 多婚礼协作
- AI 自动排座
- 签到、邀请函、礼金、流程管理
- 座位图导出图片

---

## 4. 页面规划

### 4.1 页面结构

- `/` 首页 / 入口
- `/guests` 宾客名单
- `/seating` 桌次安排

### 4.2 页面职责

- 宾客名单页：录入、筛选、统计、导入导出
- 桌次安排页：画布、桌子、座位、未入座宾客、保存

---

## 5. UI 实施原则

### 5.1 视觉规范

- 背景：暖白或纸感浅色底
- 主色：漫画红、英雄蓝、警示黄
- 辅助：黑色粗边框、半色调点阵、强调阴影
- 组件：高辨识度按钮、清晰表单、密度适中的列表

### 5.2 交互规范

- 所有关键操作必须有明确反馈
- 拖拽、保存、删除、导入都要有状态提示
- 空状态、加载态、错误态必须补齐

### 5.3 风格落地方式

- 宾客名单页偏“信息面板”
- 桌次安排页偏“漫画分格画布”
- 重点动作用动效增强，不靠装饰堆叠

## 6. 技术方案

### 6.1 前端

- Vue 3
- Nuxt
- TypeScript
- Pinia
- Tailwind CSS
- Motion
- @nuxt/ui
- vue-router
- VueUse + 原生 Pointer Events / dnd（拖拽）

### 6.2 数据层

- Supabase
- 本地状态先行，保存时同步后端

### 6.3 核心模块

- `stores/guest.ts`
- `stores/seating.ts`
- `stores/wedding.ts`
- `components/guest/*`
- `components/seating/*`
- `composables/useGuests.ts`
- `composables/useSeating.ts`
- `utils/excel.ts`
- `utils/statistics.ts`

---

## 7. 数据模型

### 7.1 核心表

- `weddings`
- `guests`
- `wedding_tables`
- `seats`
- `layout_items`

### 7.2 核心关系

- 一个婚礼对应多个宾客
- 一个婚礼对应多个桌子
- 一张桌子对应多个座位
- 一个宾客最多对应一个座位
- 舞台和 T 型台统一存入布局项

---

## 8. 开发阶段

### Phase 1：项目骨架

- 初始化 Nuxt + Vue3 + TypeScript + Tailwind + Pinia
- 建立默认布局、导航、主题变量
- 建立基础类型与目录结构

### Phase 2：宾客模块

- 宾客列表页
- 宾客新增、编辑、删除
- 搜索与统计
- 分类与所属字段

### Phase 3：Excel 能力

- 导入模板解析
- 数据校验与预览
- 导出当前宾客数据

### Phase 4：桌次基础

- 桌次页画布
- 新增圆桌
- 桌子名称与容量编辑
- 桌子拖拽

### Phase 5：排座能力

- 未入座宾客列表
- 拖拽宾客入座
- 点击安排座位
- 移动宾客到其他桌
- 移除座位

### Phase 6：现场元素

- 舞台
- T 型台
- 画布布局保存

### Phase 7：体验优化

- 动画反馈
- 对齐辅助线
- 自动吸附
- 撤销 / 重做
- Loading / Empty State

---

## 9. 交付顺序

建议按下面顺序推进：

1. 项目初始化
2. 数据结构与 Store
3. 宾客 CRUD
4. 宾客统计与搜索
5. Excel 导入导出
6. 桌次画布
7. 新增桌子与拖拽
8. 宾客排座
9. 舞台与 T 型台
10. 保存与体验优化

---

## 10. 验收标准

### 10.1 宾客模块

- 能新增、编辑、删除宾客
- 能搜索宾客
- 能看到统计数据
- 能导入、导出 Excel

### 10.2 桌次模块

- 能新增桌子并拖拽
- 能给宾客安排座位
- 能移动与移除座位
- 能保存当前布局

### 10.3 UI 标准

- 风格统一
- 状态明确
- 画布可操作
- 表单可读性稳定

---

## 11. 风险与约束

- 漫画风格容易过强，必须控制装饰密度
- 画布拖拽和座位计算要提前定数据协议
- Excel 导入需要严格校验，避免脏数据直接进入主流程
- MVP 阶段不做复杂权限与协作，避免范围膨胀

---

## 12. 本次开发目标

本阶段目标不是“做全”，而是先交付一个可以真实使用的版本：

- 能录宾客
- 能看统计
- 能拖桌子
- 能排座
- 能保存

这就是第一版的成功标准。
